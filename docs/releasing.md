# Releasing the app

Publishing a GitHub release builds a single-file executable of the Python app and attaches it to that release. Nothing needs to be installed on the exhibit PC.

## Cut a release

1. On GitHub open the repository, then **Releases** -> **Draft a new release**.
2. Create a new tag such as `v1.0` (this text becomes the version shown in the app).
3. Give it a title and click **Publish release**.

## Watch the build

Open the **Actions** tab and select the "Build release binary" run. The "Set up job" step shows which Runner Image was used. The build takes a few minutes. When it succeeds, `polygraph-<tag>-windows.exe` appears under **Assets** on the release page. If the run fails, open the failed step for the log; after fixing, re-run the job from the Actions tab (the upload overwrites an existing asset).

## Using the exe

- **SmartScreen.** The exe is deliberately unsigned, so Windows shows "Windows protected your PC" on first run. Click **More info** -> **Run anyway**.
- **Slow start.** The single-file build unpacks itself on every launch, so the window takes a few seconds to appear.
- **Console window.** A black console window stays open behind the app. Leave it open: it shows errors if something goes wrong. Closing it closes the app.
- **Version.** The window title shows the release tag, e.g. "GSR Polygraph v1.0". A run from source shows "dev".
- **Measurements.** Recordings are saved in a `measurements/` folder next to the exe, created on launch. When replacing the exe with a newer version, keep this folder (put the new exe in the same place).

## Build for Linux Mint

The workflow has a commented-out `ubuntu-latest` entry in the build matrix (`.github/workflows/release.yml`). Uncomment it to also attach `polygraph-<tag>-linux`; the `python3-tk` install step is already in place and only runs on Linux. On Linux, make the file executable (`chmod +x`) before running it, and the user needs permission for the serial port (`sudo usermod -aG dialout $USER`, then log out and in).

## Notes

- Dependencies come from `python_app/requirements.txt`. PyInstaller is installed by the workflow only.
- `python_app/_version.py` is generated by the workflow and git-ignored. `gsr_diagnostics.py` is a separate command-line tool and is not packaged.
- To try a build locally: `pip install -r python_app/requirements.txt pyinstaller`, create `python_app/_version.py` containing `VERSION = "v0.0-local"`, then run `pyinstaller --onefile --name polygraph-local --paths python_app python_app/main.py` and delete `_version.py` afterwards.
